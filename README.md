# 秋招手帖

一个在自己电脑上运行的秋招投递工作台。记录投了哪里、到了哪一步，以及下一场笔试或面试是什么时候。

**本地保存 · 无需账号 · 无需购买服务器或域名 · 基础功能无第三方运行依赖**

## 快速开始

需要 **Python 3.9 或更新版本**，以及现代浏览器。正常使用不需要 Node.js。

```sh
git clone https://github.com/VanceRUYI/offer-tracker.git
cd offer-tracker
python3 server.py --open
```

浏览器会打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。运行期间保留终端窗口，按 `Control+C` 停止；下次运行同一命令即可继续使用。

macOS 也可以双击项目内的 **启动秋招手帖.command**。该脚本使用 `/usr/bin/python3`；如果 Python 安装在其他位置，请使用上面的终端命令。下载 ZIP 后如提示没有执行权限，可先执行：

```sh
chmod +x 启动秋招手帖.command
```

端口被其他程序占用时：

```sh
python3 server.py --port 8766 --open
```

## 能做什么

| 功能 | 使用方式 |
| --- | --- |
| 记录投递 | 公司、岗位必填，岗位编号、批次选填；保存后自动归入公司并突出新记录 |
| 公司分组 | 默认按公司收纳并收起，点击公司行展开查看岗位，也能切换为按投递平铺 |
| 跟进进度 | 展开公司，点击岗位详情，通过“添加进展”记录测评、笔试、面试、Offer 等变化 |
| 详情卡片 | 默认靠右，桌面端可拖动标题栏左右移动；未填写的信息自动隐藏 |
| 待办与日历 | 默认查看近 7 天，也能按年月日查看安排；点事项打开对应投递 |
| 日期与时间 | 统一的日期浮层，支持翻月、选择年份、回到今天和输入时分 |
| 投递入口 | 保存官网或岗位链接，之后直接打开 |
| 辅助识别 | 粘贴岗位网址或通知文字，核对识别结果后再填入表单 |
| 搜索与筛选 | 按公司、岗位等关键词搜索，结合阶段、重点关注、企业性质筛选 |
| 导出与备份 | 完整 JSON 备份、CSV 表格导出，以及本地 SQLite 自动快照 |
| 个性化寄语 | 修改首页寄语、侧栏标题和正文，选择同风格图标，支持预览和恢复默认 |

界面适配宽屏表格和窄屏卡片。“看看示例”使用虚构数据，可试选阶段、勾选和恢复待办，不会写入你的记录。

待办勾选完成后保留在清单底部，可切换显示或隐藏（记住本机偏好）。完成事项保留原安排时间，并随完整备份导出；再次点击勾选可恢复。若同一岗位已有新的待办，需先处理当前待办，避免覆盖。

## 日常怎么用

1. **新增投递**：先填公司、岗位，可附投递链接和岗位编号。编号按文字保存，保留前导零，支持搜索、编辑及 JSON / CSV 导出。企业性质、城市、渠道、简历版本和备注放在“更多信息”中。
2. **收到通知**：展开公司，点击对应岗位的“详情”，选择“添加进展”，更新当前阶段。
3. **记录安排**：在“下一步”填写“参加一面”等事项，再选“安排时间”，就会出现在待办和日历中。
4. **完成后跟进**：在待办或详情中标记完成；完成记录保留在时间线，再添加下一步安排。

详情卡片默认在右侧；桌面端拖动标题栏可左右移动，双击标题栏回到默认位置，也可聚焦标题栏后使用左右方向键移动、Home 或 Enter 复位。卡片内容可正常滚动，空白选填项不展示。

每份投递有 **一个当前待办**，可以修改时间或内容；没有时间的事项单独列为“时间待定”。结束投递会清除当前待办，保留历史。

### 同公司多个岗位与重复投递

- 直接点击“新增投递”：公司名相同会自动归组，忽略首尾空格和英文大小写。输入名称时会提示已有公司；简称只给建议，选中后才归入对应公司。
- 公司分组内点击“添加岗位”：自动填写公司和企业性质，再填写新岗位即可。
- 同公司、同岗位已有记录时，可以选择“更新已有投递”继续记录进展；重新投递则勾选“仍然新增一次投递”。“批次 / 备注标签”选填，例如“提前批”“正式批”“2027 春招”。
- 一面、二面、终面属于一次投递的进展，通过“添加进展”记录，无需新建投递。
- 每次投递保留独立的链接、状态、待办和时间线。日历和待办会显示岗位与批次；未填批次的重投用日期区分，同标签重投再补充序号。
- 列表默认按公司收纳，也能切换为按投递平铺。筛选只显示匹配的投递，分组标明匹配数量；统计分别说明投递次数和公司数。

企业性质选填；所属行业已从日常界面移除，旧记录中的行业数据仍保留在导出中。

首页点击侧栏寄语旁的编辑按钮，可以修改文字，并从叶子、太阳、星星、爱心、咖啡、指南针中选择图标。编辑时实时预览，保存后生效；“恢复默认”也需要保存。今日和逾期待办仍优先于首页寄语显示。设置保存在本机数据库，刷新后仍保留。

## 网址能自动识别到什么

- 支持部分公开招聘页的标准 JobPosting 信息、明确中文字段和岗位标题，以及粘贴的岗位详情、投递通知、面试邀请。
- 公司、岗位、城市和企业性质需要有明确依据；个人投递日期、进度和安排不会仅凭招聘页面猜测。招聘发布日期不会被当作投递日期。
- 识别结果只展示字段和值，按需勾选后点击“填入表单”，最后再保存投递。结果可以修改，不能确定的信息留空。
- 普通读取拿不到公司或岗位时，会尝试用本地 Chromium 加载动态页面，读取显示出来的正文及页面加载的岗位数据。支持常见字段结构，不依赖特定公司的接口地址。公司和岗位已识别时立即返回；仍缺少核心信息且已配置免费 GLM 时，才由模型整理已读取的内容。
- 支持从当前岗位标题末尾提取 `J100700`、`REQ-001234` 等括号内编号，保留前导零和完整岗位标题；年份、届数及网址末尾的字符串不会仅凭位置自动填成编号。
- 动态读取可提取有依据的公司、岗位、城市、岗位编号和批次，并记录页面图标地址；图标在保存后后台获取，不阻塞识别，结果仍需勾选确认。职位列表不自动选择第一项，公开职位的“招聘中”不会当作个人投递进度。
- 需要登录、验证码、限制访问、已下架或特殊结构的页面仍可能无法识别，可改为粘贴文字或手动填写。多个安排、缺少年份或模糊时间需手动核对。

这是辅助录入工具，不是自动投递工具，也不会登录你的招聘账号。网络访问细节见[开发说明](docs/development.md#网络与隐私)。

程序会自动记住成功读取页面所用的公开岗位 GET 数据入口。同一招聘网站、同一路径形式的后续岗位会优先直接读取，已有明确字段时不再等待模型。入口仅保存在当前服务内存中，最多保留 32 条、有效期 6 小时，重启后重新学习；不复用签名请求、跨站接口或 POST 请求。首次访问的新网站、不同路径和需要登录的页面仍可能较慢，不能保证所有链接都在 5 秒内完成。

### 增强网址识别

动态页面读取是可选组件，不影响基础记录和备份。macOS / Linux 在项目目录执行一次：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-browser.txt
PLAYWRIGHT_BROWSERS_PATH=.browser-runtime .venv/bin/python -m playwright install chromium
```

Windows PowerShell：

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements-browser.txt
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.browser-runtime"
.venv\Scripts\python -m playwright install chromium
```

随后照常启动工作台。程序会自动使用项目内的组件，不需要配置 API Key。浏览器文件只保存在本机，已加入 Git 忽略。首次下载需要联网和数百 MB 空间；动态读取耗时取决于网站和网络；拿到公司和岗位后直接返回，复杂页面仍可能较慢，并有超时限制。未安装时会保留普通读取结果并提示安装或粘贴文字。

### 可选：免费 GLM 识别

在项目目录创建 `.env.local`，填入智谱开放平台的 API Key：

```dotenv
ZHIPU_API_KEY=你的密钥
```

配置后，点击“识别网址”会先读取网页，需要整理时调用 `glm-4.7-flash` 提取公司、岗位、编号、城市和批次。结果区仅展示可勾选的字段和值，点击“填入表单”后再保存投递。模型仅接收公开网页的标题、截取正文和岗位字段线索，不发送你的投递记录、简历或备注。普通模型接口不会自行打开网址，动态页的加载时间仍然存在；复杂招聘网站首次读取仍可能超过 20 秒。读取器支持压缩资源与本次临时访客会话，不使用你的浏览器登录信息。

密钥仅由本地后端读取，`.env.local` 已被 Git 忽略，不进入网页或备份。也可使用环境变量 `ZHIPU_API_KEY`（优先于文件）。无需安装额外模型 SDK；删除本地配置及对应环境变量即可回到规则识别。

模型固定使用免费版本，关闭深度思考，每次仅请求一次，不自动切换付费模型。模型网络等待超时设为 3 秒，避免服务无响应时长时间阻塞；已有公司和岗位时不会为补齐选填信息调用模型。免费额度和限流以平台为准。调用失败、限流或输出无依据时，保留已识别的字段供确认。提取值会做原文存在性检查，但不能替代人工核对；填入后仍需确认保存。粘贴文字识别保持本地规则处理。

## 数据存在哪里

默认数据库位于 `data/workbench.sqlite3`，**不在浏览器缓存中**。关闭网页、清理浏览器缓存不会删除它。程序只监听本机回环地址，不向外提供服务。

`data/`、数据库文件、备份、导出文件、环境变量和常见缓存已配置 Git 忽略规则；GitHub 仓库保存代码，不能替代你的投递数据备份。

### 导出与自动备份

- **JSON**：包含完整投递、时间线和个性化设置，可在另一份工作台中合并导入。
- **CSV**：适合用表格查看，不包含完整时间线。
- **自动快照**：每天首次启动时生成 `data/backups/YYYY-MM-DD-daily.sqlite3`；导入和删除前也会生成快照。

JSON 导入只补充新记录，**不会覆盖已有记录或合并其后续进展**。新版（version 2）按记录编号去重，同岗位不同投递都会保留；旧版（version 1）仍按编号或公司、岗位去重。新版备份需使用支持 version 2 的工作台恢复。目前不直接支持飞书表格或其他工具的备份格式。

个性化设置仅在本机尚未保存过设置时恢复，已有设置会保留；没有个性化字段的旧备份仍可导入。

建议定期把 JSON 另存到其他磁盘或自己的备份位置。同一磁盘上的快照无法防止整盘损坏。

### 从 SQLite 快照完整恢复

1. 关闭工作台服务，在终端按 `Control+C`。
2. 将当前 `data/workbench.sqlite3` 另存留底。
3. 复制需要的 `data/backups/` 快照到 `data/`，命名为 `workbench.sqlite3`。
4. 重新启动工作台，并保留原始快照。

### 公司图标

- 腾讯、字节跳动、阿里巴巴支持按准确名称或内置别名，从已核对的官方网站自动获取图标。首次获取需要联网，成功后保存在本机。
- 保存带投递网址的记录后，会在后台尝试补齐公司图标，已有记录也适用。内置名单之外的公司，会核对页面招聘信息里的公司名称；名称匹配且不属于已知招聘平台时，尝试读取网站图标。无需额外点击，失败不影响保存投递。
- 自动获取会排除飞书、北森、Moka、BOSS 直聘等常见平台域名及跳转结果；无法确认公司、页面需登录或没有可用图片时，显示统一的企业线条图标。平台覆盖并不完备，识别有误可手动替换。
- 同名公司的所有岗位共用图标。需要调整时，在详情中点击图标，填写官网获取预览或上传 PNG / JPG / WebP 图片。手动设置和“使用默认图标”优先，不会被自动覆盖。
- 图标存于本地 SQLite，并随完整 JSON 备份导出、恢复。已有本机图标优先，导入不会覆盖；旧版程序导入新备份时可能忽略图标。
- 示例中的腾讯、字节跳动、阿里巴巴用于图标效果演示，岗位、进展和其他示例信息均为虚构。
- 图标分别来自 [腾讯官网](https://www.tencent.com/)、[字节跳动官网](https://www.bytedance.com/)、[阿里巴巴集团官网](https://www.alibabagroup.com/)，相关商标归其各自所有；仓库不打包这些图片。
